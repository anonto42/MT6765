# M3.2 device subsystem live, M3.3 input subsystem live
Status: done on the host (unit, integration and real-Xvfb tests); NOT yet run on the tablet
Files changed: crates/walpad-core/src/{brain,xbridge,inputs,apps,daemon,shadow,shadow_live,main,lib}.rs, crates/walpad-core/tests/{live,ipc}.rs, crates/walpad-hw/src/sysfs.rs, config/rootfs/sbin/walpad-init, config/rootfs/usr/local/sbin/walpad-runtime, tests/shell/run.sh, scripts/{rust,build_rust,check}.sh, scripts/ci/Dockerfile
What works now:
 - Brain: one decision engine (screen timeout, cover, power key, rotation, battery guard, volume gestures, touch map) emitting typed Effects. Shadow mode prints them as WOULD lines (unchanged format); live mode executes them.
 - walpad-core --device / --input run the subsystems live; flags come from walpad-runtime via walpad-init. Device: backlight, orientation file, struts + keyboard docking through X, power menu (spawns the existing Tk walpad-powermenu.py; short press while open sends Return), cover, battery guard with `poweroff -f` after sync, devd.cmd FIFO, status.json. Input: touch -> XTEST pointer (calibration + orientation), volume gestures -> key:/ctl:/launch:/home/keyboard/screenshot/volume; `run:` is rejected and logged.
 - X bridge (x11rb, pure Rust): every wait has a 2 s deadline (custom Stream), lazy connect with backoff, resync of struts/keyboard after X restarts, 5 s liveness ping, button released if the bridge drops.
 - IPC commands now real: launch (allowlist, contract env, single-instance focus via WM_CLASS, installed-only), home, keyboard, screenshot, restart_shell, set_setting (allowlisted keys, atomic rewrite, live reload), power (confirmed only; real halt only when the root is `/`). Child reaping is non-blocking. wifi_* is still M4.
 - Capabilities: `walpad-core --capabilities` = "ipc shadow device input". walpad-runtime requires DEVICE=rust for INPUT=rust (wake-swallow depends on the device subsystem).
Checks run: scripts/check.sh -> ALL CHECKS PASSED. Tests include: 4 live-mode tests over fake roots (power key -> backlight 0, cover -> off, gsensor -> orientation 90, flags gate each subsystem) and a touch test against a real Xvfb for orientations 0/180/90/270 (pointer lands where the contract table says); X bridge tests for struts, pointer, keys, keyboard docking; IPC tests for the new commands. aarch64 binary under qemu: --capabilities, --fake --device --input, ctl brightness/rotate verified.
Bug found by the live tests and fixed: hw::write_backlight did not truncate (harmless on sysfs, wrong on regular files).
