# M5.5 Apps and Network screens, password sheet with the built-in keyboard
Status: done on the host (unit, 17 goldens, full-stack click-through against a real core + fake supplicant + Xvfb); not yet on the tablet
Files changed: crates/walpad-shell/src/{app,app/tests,apps_screen,network,overlay,core_client,shell,lib}.rs, crates/walpad-shell/tests/{x,screens_snapshots}.rs, crates/walpad-shell/tests/golden/* (17 new), crates/walpad-proto/src/{command,tests}.rs, crates/walpad-core/src/daemon.rs, crates/walpad-core/tests/ipc.rs
What works now:
 - Apps: grid of installed apps (2 columns portrait, 4 landscape) plus the Settings shortcut; the Wi-Fi app entry is not shown (the Network tab replaces it). Tap launches; long press opens a sheet with Close app (only if running), Pin to / Unpin from Home, Cancel. Pins are saved through the new `pinned_apps` setting (shell.json) and drive the Home tiles.
 - Network: header with radio chip (Up/Starting/Failed + "Restart the tablet to retry Wi-Fi"), connected card (SSID, signal, IP, Disconnect), Scan button (spinner, disabled while scanning, single flight), available networks (72 px rows, lock, four-step signal, Connected/Connecting state), saved networks with Forget behind a confirmation dialog, empty/scanning/error states.
 - Tapping an available network: stored credentials -> connects by saved id; open -> connects at once; secured -> password sheet with the on-screen keyboard (lower/upper one-shot shift/symbols, show/hide, 64-char cap, Connect disabled until the secret is a valid WPA2 passphrase or 64-hex key). Results: success toast and the sheet closes; "Wrong password" / "Timed out after 25 s" / the core's message shown inline with the typed text kept for a retry.
 - Scrolling: tall screens are drawn off-screen at full height and the visible slice is copied; drag scrolls (clamped), taps hit the right row at any offset, switching tabs resets it.
 - Toasts (3 s) and a 10 fps spinner that only runs while something is in progress; the loop wakes exactly for those deadlines.
 - The core client now returns request ids and `Reply` events (data + protocol error code); the app maps replies to purposes (saved list, scan, connect, forget, close).
 - Protocol/core: new `close_app` command (stops what the core started; reports `closed:false` honestly otherwise) and `pinned_apps` setting (max 8 valid ids).
Security: the typed secret lives only in the open sheet, is cleared on cancel, `Cmd`'s Debug prints `***`, and it is serialized in exactly one place (onto the control socket). The full-stack test asserts the passphrase never reaches the supplicant (only the PBKDF2-derived key).
Checks run: scripts/check.sh -> ALL CHECKS PASSED. 43 shell unit tests (flows: launch/close/pin, scan single-flight and error, open and secured connect, wrong password then success, timeout, shift/symbols/length cap, saved connect and forget confirmation, stored-credential shortcut, disconnect/core loss reset, scrolling with taps at an offset, spinner/toast timing, request shapes); 17 goldens inspected by eye; full-stack click-through: Network tab -> Scan -> results -> tap Home -> type "correct horse" on the keyboard -> Connect -> the core reports Home and the sheet closes (3/3 runs).
Measurements: walpad-shell 1,283,768 bytes, walpad-core 1,007,360 (release, stripped, static aarch64).
Device checks pending: none yet (the shell is still not selectable: `walpad-shell --capabilities` is empty until M5.9).
Deviations from plan: no search field (fewer than 12 apps); Scan sits on the section-label row; the sheet has no scrim (the design forbids transparency).
Known limitation: Close app only works for apps the core started; an app started by the old Python launcher cannot be closed from the Apps sheet (toast says so).
