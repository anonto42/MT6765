# M5.10 System keyboard (owner request 2026-11-10: replace matchbox-keyboard)
Status: done on the host (unit tests, 4 goldens inspected by eye, Xvfb test with XTEST, core IPC test); not yet on the tablet and not tried under openbox
Why: on the device openbox maximised matchbox-keyboard to 800x1280 (its image tiled 3 times), it could not be typed on, and Xvfb burned ~85 % CPU in a redraw loop while it was open.
Files changed: crates/walpad-shell/src/{keyboard (new),dock,shell,app,core_client,lib}.rs, crates/walpad-shell/Cargo.toml (x11rb `xtest` feature, pure Rust, already a dev-dependency), crates/walpad-shell/tests/{keyboard_snapshots (new),x}.rs, crates/walpad-shell/tests/golden/keyboard_* (4 new), crates/walpad-ui/src/components.rs (system keyboard component), crates/walpad-proto/src/command.rs (ShellInput::KeyboardShow/KeyboardHide), crates/walpad-core/src/daemon.rs, crates/walpad-core/tests/ipc.rs, docs/rust/{CONTRACTS,UI,TASKS}.md
What works now:
 - `walpad-keyboard`: override-redirect window on the shell's own X connection (the dock pattern), full width, 30 % of the visible height flush with the bottom (portrait 0,896 800x384; landscape 0,560 1280x240), WM_HINTS input=false; a managed 1x1 `walpad-keyboard-strut` window (`_NET_WM_WINDOW_TYPE_DOCK`) carries the bottom strut (384 portrait, 720 landscape = 480 below the panel + 240). Follows rotation like the dock (area from the shell's aspect).
 - Layout (walpad-ui `system_keyboard_layout` / `Painter::system_keyboard`): 5 rows, 12 key units: Esc Tab 1-0 / q-p Backspace / Ctrl a-l Enter / Shift z-m . Up / / ?123, minimise, space, Left Down Right; a symbols layer. Landscape keys are 42 px high, portrait 68. Line-art tokens; pressed or latched = 10 % fill + white outline.
 - Keys are injected by the shell with XTEST into the focused window (keysym -> keycode from the server keymap, the same rule as the core's xbridge; Shift added for shifted keysyms, Ctrl/Shift latches held around named keys). Shift and Ctrl are one-shot. A tap counts on release on the same key.
 - Show/hide: dock Keyboard button and Quick Settings Keyboard toggle it locally (Cmd::KeyboardToggle is handled by the shell loop, never sent as a toggle); the shell reports its state to the core with `keyboard show|hide` (also on every core (re)connect). The core's `keyboard` command (walpad-ctl, the `keyboard` key action) publishes `keyboard_show|keyboard_hide` on the `input` topic, resolving toggle against the reported state, and answers shown/hidden ("unavailable" if no shell listens). Shown when the shell sees the `apps` event `started` for `terminal` (the shell now subscribes to `apps`). Hidden by the minimise key, the dock's Home, the core's Home key action, and whenever `_NET_ACTIVE_WINDOW` changes from another window to the shell.
 - While both are up the dock sits directly above the keyboard (portrait y 840, landscape y 504) and its strut covers both (440 / 776).
 - The core never spawns matchbox-keyboard and no longer opens a keyboard on `launch terminal`; the delayed matchbox docking (`dock_at`) is gone. `Effect::KeyboardDock` / `dock_keyboard` stay (they find no matchbox window and do nothing; the Python runtime still uses them through devd).
