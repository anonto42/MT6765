What works now:
 - Running detection: an app counts as running when we started it OR a client window with its apps.json `wm_class` exists (apps started by the Python launcher or by hand). The core scans windows every 0.7 s (_NET_CLIENT_LIST, falling back to the first 3 levels of the window tree when the WM does not publish it). `status.apps` uses this.
 - `wm_class` matching changed from "substring of WM_CLASS" to: equals the instance or class name (any case), and only needles of 4+ chars may match as substring. Reason: the old rule made `st` match any class containing "st".
 - Single instance: launching a single_instance app that has a window sends _NET_ACTIVE_WINDOW and spawns nothing ("focused"); without a window but with a live child of ours it answers "already_running". Tested both ways.
 - Close app: our own child gets SIGTERM, SIGKILL after 3 s if it ignores it (reaped non-blocking each tick). An app we did not start gets WM_DELETE_WINDOW (ICCCM ClientMessage); if its window survives 3 s the core sends SIGTERM to _NET_WM_PID (never pid <= 1 or itself); a window that does not advertise WM_DELETE_WINDOW goes straight to the signal. Reply: `{"closed":bool,"how":"terminate"|"window_close"|null}`. While closing, an app is reported as not running; a relaunch during that moment answers `busy`.
 - `apps` topic events: `{"kind":"started","app","pid"}` (or `"external":true` when a window appeared), `{"kind":"exited","app","closed":bool}`, `{"kind":"crashed","app","code","signal"}`. Every X call goes through walpad-x (2 s deadline per wait).
 - M6.2: `status.apps` lists an app only if its executable exists (checked on every status, so an app disappears when its binary does). Tested: hidden at start, launch refused (`refused`), hidden again after the binary is removed while the core runs, close_app on it is `closed:false`.
 - M6.3: a child that exits non-zero or by signal, and was not closed by us, publishes `notice` `{"kind":"app_crashed","app","name"}` and the core raises the window titled "WalPad Home". Clean exit (0) and our own Close app (even SIGTERM/SIGKILL exits) publish no notice and do not raise anything. New optional apps.json key `exit_ok: [codes]` marks extra exit codes as normal (not set in the shipped apps.json: config/rootfs was out of this card's lane).
 - Shell: subscribes to `notice`; `CoreEvent::Notice` -> Danger toast "<Name> closed unexpectedly" (3 s), other kinds ignored.
