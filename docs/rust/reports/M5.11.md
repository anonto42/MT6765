# M5.11 Dynamic keyboard (XIM) + collapsible dock (owner request 2026-11-10)
Status: done on the host (unit tests, Xvfb tests, 5 goldens inspected, plus a manual end-to-end run on Xvfb with a real GTK3 app, xterm and Firefox ESR); not yet on the tablet / under openbox.
Why: the system keyboard should behave like on a phone (up when a text input is tapped, down when the focus leaves it, not just because an app is open), and the dock strip should not take screen space.
Files changed: crates/walpad-shell/src/{ime (new),dock,shell,lib}.rs, crates/walpad-shell/Cargo.toml (+ `xim` 0.5.0), Cargo.lock, crates/walpad-shell/tests/{x,dock_snapshots}.rs, crates/walpad-shell/tests/golden/dock_{handle_portrait,handle_landscape,handle_portrait_pressed,expanded_portrait,expanded_landscape}.png (new), crates/walpad-core/src/apps.rs (CONTRACT_ENV), config/rootfs/usr/local/sbin/walpad-session, config/rootfs-nopython/files/usr/local/sbin/walpad-session, docs/rust/{CONTRACTS,UI,TASKS}.md
What works now:
 - XIM server `@server=walpad` in the shell (`ime::ImServer`, own timed X connection, built on the xim crate's x11rb server). Offers only PreeditNothing/None + StatusNothing/None, answers every CreateIC with SetEventMask(0, 0) and never consumes a forwarded event: keys never pass through it. `_XIM_XCONNECT` is handled by the shell itself so it can watch the client's window (DestroyNotify = client gone, e.g. killed); Xlib's `_XIM_MOREDATA` chunks are reassembled. Protocol errors of one client are logged, never fatal.
 - Focus state machine (`ime::FocusKbd`, pure): SetICFocus -> show after 150 ms if an input still has the focus (no flash when a window activation briefly restores the focus to its last input); UnsetICFocus / DestroyIC / Close / Disconnect / client window destroyed -> hide 250 ms after the last focused IC went away (no flicker between fields). Minimise key = down until the next focus-in. Dock Keyboard button / core `keyboard` / Home / mouse pad = manual (opened by hand with nothing focused it stays; opened while a field is focused it follows that field). The terminal auto-show became a fallback: only when no XIM client connected or focused within 3 s of the `started` event, or at once when the XIM server is not running.
 - Apps get `XMODIFIERS=@im=walpad GTK_IM_MODULE=xim QT_IM_MODULE=xim` (CONTRACT_ENV; both session scripts, the Python one only when WALPAD_SHELL=rust). The rootfs has `im-xim.so` but no `immodules.cache` (apk --no-scripts), so GTK would ignore GTK_IM_MODULE: the session now runs `gtk-query-immodules-3.0 --update-cache` once when the cache is missing.
 - Collapsible dock: `walpad-dock-handle` 56x28 (SHAPE-rounded top corners, strip colour, CARD_BORDER outline, white chevron) at the right end of the bottom edge, no strut, while a foreign app is active. Tap -> strip + strut, handle on top with the chevron down; folds after an action, 5 s idle (`dock::Fold`) or a second tap. Above the keyboard / mouse pad when one is up. Override-redirect + WM_HINTS input=false for both.
Coverage by app (verified on host Xvfb with the same binaries' protocol, not on the tablet):
 - GTK3 entries (python GTK3 test app, GTK_IM_MODULE=xim): focus entry -> up, entry -> entry no flicker, entry -> button -> down after 250 ms, typing "abc" through XTEST lands in the entry (keys not broken). Covers PCManFM's path bar / rename / search entries.
 - xterm (Xlib XIM, same path as st): focus -> up, killing it -> down. st uses the same Xlib calls (XSetICFocus on FocusIn) with XIMPreeditNothing|XIMStatusNothing.
 - Firefox ESR (GTK3): URL bar focused -> up, click into the page -> down, URL bar -> up.
Limits: Firefox password fields use GtkIMContextSimple (no XIM), so the keyboard hides there; use the dock Keyboard button. Widgets without an input context (GtkTreeView/IconView, terminals without XIM, Tk) never report focus. Qt apps need the Qt XIM plugin (none installed today). Firefox focuses the URL bar on about:blank, so the keyboard comes up when the browser starts.
