# M5.4 Home, status bar, navigation with real data; core client; offline banner

What works now:
 - Core client: non-blocking connect, hello + subscribe(status, wifi), status events parsed into walpad-proto::Status, fire-and-forget commands, `Error` notices for rejected requests, automatic reconnect every 2 s when the core is not there (tested: core stopped and restarted).
 - Home per the spec: date line + clock (updated on the minute boundary, 24 h or 12 h from /etc/walpad/shell.json `clock_24h`, 12 h shows "2:22" + PM), Wi-Fi card (SSID, "Connected" when only an address is known, "Not connected", error when the radio failed; IP in mono), Battery card (gauge value, "~62%" + "Estimated from voltage" when it is a voltage estimate, "Unknown" when null, "Charging"/"Full" in the title), Apps tiles (first four of browser/terminal/files that the core says are installed, plus the Settings shortcut; running dot), brightness slider (tap or drag, commands rate-limited to one per 80 ms plus the final value, minimum 1 so a slip never turns the screen off, "--" when there is no data), Rotation / Keyboard / Screen off buttons wired to the core. Taps: tile -> launch, Wi-Fi card -> Network tab, Battery card -> Device tab, Settings tile -> Settings tab.
 - Status bar shows the real SSID / percent / estimate flag; persistent banners: "System service not responding" when the core socket is down (buttons and slider are disabled, navigation still works) and "Battery low - connect the charger" until charging.
 - The loop waits on the X socket and the core socket together and wakes for the long-press timer, the minute boundary and core reconnects; redraws only when something changed.
Checks run: scripts/check.sh -> ALL CHECKS PASSED. New tests: client (connect, status, command effect, error notice, disconnect, reconnect), app logic (tiles, taps, offline, low battery, slider rate limit + final value, clock formats, catalog/settings files), Home layout (portrait fits without scrolling with and without a banner, tiles are 364x160, landscape = one row of 4, no overlapping rects), 6 golden snapshots (portrait, landscape, offline portrait/landscape, low battery + unknown + 12 h, charging + failed radio) all inspected by eye, and a full-stack test: real core daemon + real shell + real Xvfb: a real click on Rotation locks rotation in the core, a click at the end of the slider sets brightness 255 and the shell then shows it, stopping the core brings up the offline banner. Run 6 times in a row without a failure.
Bugs found and fixed along the way:
 - The "banner gone" check in my full-stack test was true before the shell had painted (the window background equals BG) and the test's core_status helper sent bogus args to get_status. Test fixed (wait for a drawn frame and no banner).
 - Real protocol hazard: a no-argument command (get_status, wifi_scan, ...) given a stray `args` object was rejected or accepted depending on serde_json map ordering (feature unification). Commands without arguments now always ignore `args` (unknown fields are ignored per the protocol); test added.
 - Honest-data fixes found in the goldens: brightness showed a made-up 0% offline (now "--"), 12 h clock had a leading zero, Wi-Fi card said "Not connected" next to an IP address (now "Connected").
