## What works (host)
- Core boots the modem once per boot when the AT channel is missing, picks up a running one, applies the persisted radio choice, polls CFUN/CPIN/CSQ/CREG/CGREG/CEREG/COPS, parses recorded transcripts incl. CME errors and URCs, sends the PIN only over the channel, runs the data script with a 40 s limit and reports failures with their reason.
- Shell: Mobile network screen, Quick Settings "Mobile data" row (bars, operator, switch), header pill bars while a SIM is present, APN and SIM PIN sheets, IMEI behind Show.

## Device checks pending
See "how to verify" in the hand-off; key points: modem boots from the core, PIN unlock, operator/signal, radio off/on persists across reboot, data on reports "data link not supported yet" until `walpad-modem-link` exists.

## Deviations
- `mobile_info` is an extra command (not in the request) so the IMEI is never in the broadcast status.
- Async results go to the existing `notice` topic (no new topic).
- `ModemState` adds `present` (installed, not running) and `failed` to present/booting/ready/absent.
- Data "off" keeps the visible state until the script finishes (no separate "disconnecting" state).

## Dependencies
None new. rustix gains the `termios` feature (raw mode on the AT pty) and, for tests only, `pty`.

## Rollback
