# Media: photos, videos and music (owner request 2026-11-11, change `media-apps-capture`)

"I want a media viewer: image, video, and audio and video viewer." Built from proven software
(mpv, gpicview) plus a small shell screen; no decoder of our own.

## What is where

| Part | Where | Notes |
|---|---|---|
| Media screen | `crates/walpad-shell/src/media.rs`, `media_worker.rs` | Home tile "Media" and Apps panel > Tools > Media. Sections Photos, Videos, Music, Recent. |
| Open a file | core command `launch {app, args: {path}}` | `walpad_proto::valid_open_path` (syntax) and `apps::resolve_open_path` (symlinks, regular file). |
| Photo viewer | `gpicview` (in the image, 0.2 MB, GTK3 already there for PCManFM) | `apps.json` entry with `"open": true`. Alternatives in the catalogue: `imv`, `ristretto`, `gthumb`. |
| Video and music player | `mpv` (catalogue "Media player", about 37 MB with libraries) | Config in `/root/.config/mpv/` (`mpv.conf`, `input.conf`, `scripts/touch.lua`). `vlc`, `audacious` also declare `open`. |
| Thumbnails and durations | `/usr/local/sbin/walpad-thumb` | Cache `/var/cache/walpad/thumbs`. Needs the optional catalogue entry "Media thumbnails" (`imagemagick`, `ffmpeg`, `ffmpegthumbnailer`). Without it the grid shows placeholders and everything else works. |
| File associations | `defaults.json` roles `video`/`music` = mpv, `image` = gpicview; `/root/.config/mimeapps.list` is generated by the core | PCManFM and Firefox use GIO, which reads `mimeapps.list`. PCManFM is configured for single tap (`libfm.conf single_click=1`): one tap on a media file opens it in the matching player. |

## The Media screen

- Photos and Videos: grid of 152 px thumbnails (4 columns portrait, 7 landscape), file name under
  each, duration badge on videos. Music and Recent: list rows with the title and artist (from the
  file tags when `ffprobe` is installed), duration, size.
- Folders searched (newest files first, at most 600 items, 4000 directory entries, depth 3, no
  symlinks followed, hidden entries skipped): `/root/Pictures`, `/root/DCIM`, `/root/Videos`,
  `/root/Movies`, `/root/Music`, `/root/Downloads`, `/tmp/Downloads`, `/mnt/sd`, every folder in
  `/mnt/usb`. The scan and all thumbnail work run on one background thread, never on the UI thread.
- Only items on or near the screen get thumbnails (about three screens), one `walpad-thumb` job at a
  time; at most 160 decoded thumbnails stay in memory (about 100 KB each).
- Tap an item: `launch {app: <player>, args: {path}}`. The player is the first installed one of
  `gpicview, imv, ristretto, gthumb` (photos) or `mpv, vlc` (video and music). Nothing installed:
  a toast says where to install one. Opening again while the player runs closes it and starts the
  new file (the core does it when the old copy has exited).
- Recent: `/var/lib/walpad/media-recent` (30 paths, written by the shell, no secrets).

## `launch` with a file (security model)

Clients still only name an app **id**. The new optional `args.path` is accepted only when:

1. the app definition declares `"open": true` (apps.json or apps.d; catalogue entries carry
   `"open": true` or an argv tail array); `open_args` is the fixed tail, default `["--", "{path}"]`,
   and the core replaces exactly the `{path}` element;
2. the path is absolute, at most 1024 bytes, has no control characters, no `.`/`..`/empty/hidden
   component, no component starting with `-`, and lies under `/root`, `/mnt`, `/home` or
   `/tmp/Downloads` (proto check, so the socket rejects it before the daemon sees it);
3. after `canonicalize` (symlinks resolved) it is still under one of those roots, still passes the
   same check, and is a regular file.

There is no shell and no arbitrary exec: the argv is `exec + open_args` with the resolved path.

## `walpad-thumb`

`walpad-thumb thumb FILE` prints the cache path of a 192x192 PNG, `walpad-thumb info FILE` prints
`duration=<s>`, `title=`, `artist=`. Exit 0 ok, 2 refused path, 3 file over 100 MB, 4 busy, 5 no
thumbnail possible. Bounds: allowed roots and symlink check as above, one job at a time (`flock`,
30 s wait), every tool under `timeout -s KILL 20`, ImageMagick memory/map/time limits, PNG at most
256 KB, cache at most 1500 files (least recently used dropped), failures cached as `.none` (a missing
tool is not cached). Tools: images ImageMagick (`magick`/`convert`), videos `ffmpegthumbnailer`
then `ffmpeg`, music embedded cover art through `ffmpeg`. Tests: `tests/shell/media_test.sh` (fake
tools).

## Player behaviour (mpv)

`mpv.conf`: `vo=x11`, `hwdec=no`, `ao=pulse`, `audio-samplerate=44100`, `audio-format=s16`,
`framedrop=vo`, 4 decoder threads, `vd-lavc-skiploopfilter=nonref`, cache 48 MiB ahead and 16 MiB
back (RAM is shared with Firefox and the shell), borderless window, `audio-display=embedded-first`
(album art for music, else a plain window), DejaVu Sans for subtitles and OSD. `vo=gpu` is not used:
Mesa is llvmpipe (software GL) and slower than the plain X11 path.

Touch (the OS gesture layer turns a tap into a click, a one-finger drag into wheel events, a
two-finger pinch into Ctrl + wheel):

| Gesture | Action |
|---|---|
| tap | play / pause (after a 0.32 s double-tap window) |
| double tap, left / right third | seek -10 s / +10 s |
| double tap, middle | fullscreen on / off |
| vertical drag | volume +-2 per step |
| horizontal drag | seek +-5 s |
| pinch | zoom the picture (`0` resets) |
| Back (dock) = Esc | leave fullscreen, else quit |
| on-screen controller | the stock OSC, bottom bar, about 2x size (`osc-scalewindow=2`), shows on touch, hides after 6 s |

`uosc`/`modernz` were not added: they are not in the Alpine repository, would be unpinned downloads
and cannot be tested here. The stock OSC with larger scale needs no extra code.

## Hardware limits (honest)

The MT6765 has no GPU user space and no usable hardware decoder here, so everything is software.
Expected (to be confirmed by the device tests in `openspec/changes/media-apps-capture/tasks.md`):

| Content | Expectation |
|---|---|
| H.264 up to 720p30 | plays; this is the target (under 5 % dropped frames) |
| H.264 1080p30 | borderline, drops frames; try `--vd-lavc-skiploopfilter=all` |
| HEVC, VP9, AV1 | 480p-720p at best; 1080p will not keep up |
| Audio | MP3, AAC/M4A, FLAC, Ogg Vorbis, Opus, WAV: all fine; decoding is cheap |
| Audio output | **44.1 kHz only**, through the PulseAudio system daemon on the safe ALSA plug (`asound.conf`); other rates are resampled by mpv/pulse, never sent raw to the driver (raw hw at other rates hangs the legacy mt-soc driver). 48 kHz material is resampled (costs a little CPU). |
| Images | JPEG, PNG, GIF, BMP, TIFF, WebP (WebP needs the pixbuf loader; else it shows no preview), SVG not listed in the Media screen |
| Formats listed by the Media screen | photos: jpg jpeg png gif bmp webp tif tiff; video: mp4 mkv webm avi mov m4v mpg mpeg 3gp flv wmv ogv ts; music: mp3 flac ogg oga opus wav m4a aac wma |
| Photo viewer gestures | pinch = Ctrl + wheel (zoom in gpicview); a one-finger drag is a wheel event, which gpicview uses to go to the next or previous picture; use the toolbar to pan. Not verified on the device. |
| Thumbnails | about 0.1-0.5 s per photo, 1-3 s per video on this CPU; they arrive while you scroll |
| RAM | mpv about 100-200 MB with the configured cache; one player at a time (the core replaces the running one) |

Unknowns to measure on the device (record results in the OpenSpec tasks): real dropped-frame rate
for 720p30 and 1080p30, A/V sync through Pulse, whether `ctrl+wheel` zooms in gpicview, the exact
double-click event order in mpv 0.41 (the script ignores a plain click that follows a double click
within 120 ms).

## Install on a fresh image

Everything except mpv and the thumbnail tools is in the image. In Settings > Apps install "Media
player" (mpv) and "Media thumbnails". The catalogue marks mpv as the default for video and music and
gpicview for images; the core regenerates `mimeapps.list` after every install.
